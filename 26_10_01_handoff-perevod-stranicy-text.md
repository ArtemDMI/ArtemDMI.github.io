# Handoff: страница перевода на фронтенде

Дата фактов: 2026-10-01. Источник: текущий чат и код репозитория.

## Суть вопроса

Пользователь описывал сайт на GitHub Pages и сценарий перевода: человек вставляет текст, текст режется на строки, у строки есть кнопка, по нажатию уходит запрос с промптом, ответ появляется под этой строкой.

Сначала вопрос был о локальном backend на своём компьютере и планшете через интернет при фронтенде на GitHub. Пользователь указал, что туннель для этой задачи не подходит. Затем пользователь указал, что обработка должна быть целиком на фронтенде: ключ в странице, запрос из браузера, страница доступна любому, кто её открыл.

Дальше пользователь задал саму страницу: тёмная, одно окно без перехода на другую страницу, поле ввода сверху, генерация строк, сброс, поле размера шрифта, кнопки перевода у строк, ответ зелёным под строкой.

## Что уже известно

- Репозиторий — статический сайт. Точка входа `index.html`. Ссылка на страницу перевода: `Pages/text.html`, подпись ссылки `text` (`index.html`, строка 57).
- Страница перевода — один HTML-файл со стилями и скриптом внутри: `Pages/text.html`, заголовок `Текст`.
- Сверху `textarea#box` на 3 строки. При загрузке вызывается `box.focus()`.
- Под полем ряд: кнопка `Сгенерировать` (`#build`), кнопка `Сброс` (`#wipe`), поле `шрифт` (`#size`, `type="number"`, начальное значение 14, min 8, max 72).
- `Сгенерировать` вызывает `splitSentences` → `groupSentences` → `render`, затем `applySize`.
- `Сброс` очищает `#box` и `#list` и снова ставит фокус в `#box`.
- `applySize` пишет `font-size` в `#list`. Пользователь указал, что смена цифры меняет размер уже построенных строк. Поле ввода сверху этим числом не управляется: у `#box` в CSS отдельно `font-size: 16px`.
- Фон страницы `#0f0f0f`.
- Строка результата — `.block`. Внутри `.line`: левая кнопка `.go` с текстом `→`, абзац `.src`, кружок `.dot`, правая кнопка `.go` с текстом `→`. Под строкой абзац `.tr`.
- Обе кнопки вызывают `send(block)`. `send` красит все `.go` этого блока: класс `ok` при ответе, класс `bad` при ошибке.
- Пока запрос идёт, у `.dot` добавляется класс `on` (вращение). Таймаут запроса 30000 мс (`AbortController` в `send`). При ошибке или пустом ответе кнопки красные 6000 мс, затем красный снимается; если в `.tr` уже есть текст, кнопки снова получают `ok`.
- Повторный `send` на том же блоке увеличивает `block._id`, обрывает предыдущий `AbortController` и по успешному ответу перезаписывает `.tr`.
- Контекст для промпта — `prior(block)`: до 5 предыдущих `.src` в `#list`, без текста перевода. Если предыдущих меньше пяти, уходят те, что есть.
- Системное сообщение в текущем коде: `Роль - ты переводчик с русского на английский язык`.
- Пользовательское сообщение в `pull` собирается так: предыдущий контекст, затем задача, затем текст `.src`. Текст задачи в файле сейчас: перевод на английский с заменой слов и выражений на эквиваленты уровня B2, разговорный язык «как два приятеля в кафе», в ответе только английский текст без заголовков (`Pages/text.html`, `pull`, около строк 266–274).
- Модель в теле запроса: `deepseek/deepseek-v4.1-flash`. Поле `reasoning.effort`: `low` (`pull`, строки 283 и 288).
- Ранее в этом же чате в запрос была записана модель `google/gemini-3.8-flash` с `reasoning.effort` `high`. Пользователь затем указал `low`. Затем пользователь указал модель `deepseek/deepseek-v4.1-flash` и `low`. В файле сейчас второй вариант.
- Адрес запроса собирает `endpoint()` из фрагментов `ha`…`pe`. Заголовок авторизации собирается как `"Bea" + "rer " + material()`.
- Ключ собирает `material()` из `u1`, `u2`, `u3` (`sk`, `or`, `v1` в разном порядке объявления), строки букв `mix`, строки цифр `lane` и маски `marks`. Цифра из `lane` при сборке увеличивается на 4 по модулю 10. Пользователь передал в чат полный ключ вида OpenRouter и указал разрезать его так, чтобы в исходнике не было цельной приставки и цельного ключа.
- В `Pages/text.html` поиском по файлу не найдены цельные подстроки `openrouter`, `sk-or`, `Bearer`, `api/v1`.
- Разбор текста: `splitSentences` режет по переводам строк и по `.!?…`. `longWords` считает слова, у которых больше 3 букв (`\p{L}`). `groupSentences` копит подряд идущие куски с `longWords <= 5`. Если после этого накопленный кусок всё ещё имеет `longWords <= 5` или бакет пуст, к нему добавляется ещё один следующий кусок. Куски склеиваются пробелом.
- Пользователь привёл пример длинной строки, которая может остаться целиком: предложение «Она боком посмотрела…» из `sources/12/vvvvvvvvsdsd.txt`. И пример склейки строк 156–158 того же файла в одну строку: реплика «Наоборот…», следующая реплика и «Я искал слово.».
- Для текста без знаков `breakUnpunctuated`: если длина больше 400 и в строке нет символов из набора `.,!?;:…—`, текст режется по пробелам так, чтобы кусок не превышал 400 символов с пробелами и не обрывался внутри слова. Если знак из этого набора есть, функция возвращает строку как один кусок, даже если она длинная.
- Ответ читает `readAnswer`: `choices[0].message.content`, строка или массив частей с полем `text`. Пустой ответ считается ошибкой.
- Отдельный локальный CLI перевода файлов в этом чате не подключался к странице. В репозитории он описан в `cursor_api/README.md`, промпт файла — `cursor_api/file_agent/prompt.md`. Пользователь начал с этого контура, затем указал другой: браузер и OpenRouter.
- Агент в этом чате не делал git commit и не публиковал страницу на GitHub.

## Файлы и связи

- `index.html` — список страниц. Ссылка `Pages/text.html`.
- `Pages/text.html` — вся страница перевода: разметка, тёмные стили, скрипт.
- `material()`, `endpoint()` — сборка ключа и URL перед `fetch` в `pull`.
- `splitSentences`, `breakUnpunctuated`, `longWords`, `groupSentences` — как вставленный текст становится строками `.src`.
- `render` — строит `.block` и вешает `send` на обе кнопки.
- `prior` — пять предыдущих исходных строк для user-сообщения.
- `pull` — `fetch` POST, модель, роли сообщений, `reasoning`.
- `send` — спиннер, 30 с, зелёный/красный, перезапись `.tr`.
- `applySize` — размер шрифта `#list`.
- `sources/12/vvvvvvvvsdsd.txt` — файл, на строках которого пользователь показывал склейку и длинное предложение. Страница этот файл сама не читает: текст попадает только через вставку в `#box`.

## Подозрительности и неуверенности

- Формулировка user-промпта в `pull` не совпадает пословно с текстом, который пользователь написал в чате. В чате было «слов и выражения эквивалентов уровню знаний языка B2» и «книжные глаголы , слова И формулировки» с лишними пробелами. В файле — «слов и выражений на эквиваленты уровня знаний языка B2» и «книжные глаголы, слова и формулировки». Кто именно правил строку после первой записи, из этого чата не следует.
- Пример склейки пользователя — ровно три строки 156–158. Реализация `groupSentences` клеит все подряд идущие куски с не больше чем 5 длинными словами, и при необходимости ещё один следующий. Отдельной проверки, что в строку попадают только 156–158 и не попадают соседние короткие строки 155 и 159, в браузере не было. Локальный прогон той же логики на этом файле собрал в одну строку пять кусков: строка 155, три строки примера и строка 159. Длинное предложение «Она боком посмотрела…» в том прогоне осталось отдельной строкой.
- `breakUnpunctuated` не режет кусок, если в нём уже есть запятая, точка, `!`, `?`, `;`, `:`, `…` или `—`, какой бы длинной ни была строка. Порог 400 символов с пробелами выбран при реализации; пользователь число не называл.
- Повторный клик по второй кнопке того же блока обрывает уже идущий запрос. Отдельного запрета на два одновременных запроса с разных строк нет: у каждого `.block` свой `AbortController`.
- Проверка, что собранный `material()` побайтно равен ключу из чата, скриптом по файлу в конце не прошла: команда с полным ключом была остановлена автоматической проверкой. До записи файла отдельный прогон разложения тела ключа на буквы, сдвинутые цифры и маску вернул совпадение с исходным телом. Строки `mix`, `lane`, `marks` в `Pages/text.html` совпадают с тем прогоном. Это не повторная проверка уже записанного файла целиком.
- Живой ответ модели в браузере не получали. Клик по `→` не выполнялся.
- Публикация на GitHub Pages из этого чата не делалась. Пока файл только в локальном репозитории, открытый GitHub Pages эту страницу не отдаёт. Это наблюдение о состоянии, не о действии.

## Допись: блоки, упрощение, список моделей, нарезка

Дата фактов: 2026-10-01. Источник: следующий чат после первой записи этого файла. Правки только в `Pages/text.html`. Git commit не делался.

### Блоки по 30 строк

- После `groupSentences` строки режутся пачками по 30. Пачка — `.pack`. Внутри те же `.block`, что и раньше.
- Кнопка пачки — «упростить», класс `.mid`, на всю ширину списка. Стоит после `Math.floor(числа строк / 2)` строк: у 30 строк это 15, кнопка, 15. У двух строк — строка, кнопка, строка. У одной строки кнопка оказывается первой.
- «Сгенерировать» и «Сброс» на месте. Кнопки `→` у строки по-прежнему вызывают `send` → `pull`.
- «Упростить» вызывает `adapt` только для своей пачки. Ответ заново проходит `splitSentences` и `groupSentences` и заменяет строки этой пачки. Число строк может стать другим. На соседние пачки это не делит текст заново.
- Пока идёт упрощение, запросы `→` внутри пачки обрываются. Повторное нажатие «упростить» обрывает предыдущий запрос этой пачки. Ожидание упрощения 120000 мс. У строки по-прежнему 30000 мс. Ошибка кнопки «упростить» — класс `bad` на 6000 мс. Успех — новый `.mid` с классом `ok`.

### Что уходит при упрощении

- И строка, и упрощение идут через одну функцию `post`. Тело: выбранная модель, `messages`, `reasoning: { effort: "low" }`. Поля `high` в файле нет.
- Модель читается из `#model` в момент отправки, не при загрузке страницы.
- Системное сообщение упрощения: адаптатор английского и русского в простой русский B2 для подростка. Русский пересказывается простыми формулировками, английский переводится на такой же русский. Детали сохраняются. Меняются порядок слов и витиеватые формулировки. Мусор убирается. Пунктуация и оформление правятся.
- Пользовательское сообщение собирает `shapeTask`. Правила: не выкидывать факты и не пересказывать короче; книжное, метафоры и иносказания заменять прямыми словами, как в новелле; порядок «подлежащее, сказуемое, остальное»; фразу из трёх и более частей дробить, две части можно оставить; язык B2 для подростка; убирать тайминги, бесполезные цифры, ники, разметку сайтов и прочий сор, факты истории оставлять; ломаную пунктуацию и форматирование исправлять; в ответе только готовый текст, без пояснений.
- Дальше в том же сообщении: прежний обезличенный пример стиля (мужчина / женщина, без имён Косаку и Санаги); пример переделки «было / стало» про подписной бонус, Секспота и Тлейси; строка «Выведи примерно в таком же виде.»; заголовок «Вот то, что нужно перевести/адаптировать:»; все `.src` этой пачки, через перевод строки.
- В образце «стало» две опечатки из сообщения пользователя не переносились: «в обмена» записано как «в обмен», повтор «ушел и ушёл» записан одним «ушёл».
- Построчный перевод на английский B2 не менялся по тексту задачи. Сменилась только доставка: `pull` тоже вызывает `post`.

### Нарезка строк

- `longWords` считает слова, у которых не меньше 3 букв (`\p{L}`). Раньше в этом файле порог был «больше 3».
- `groupSentences` копит куски, пока в строке меньше 7 таких слов, затем закрывает строку. Хвост короче 7 слов приклеивается к предыдущей строке, если она есть.
- Промежуточный вариант, от которого пользователь отказался: не давать строке перевалить за 5 длинных слов. Он резал диалог про триллионы на 6 строк и оставлял в `sources/12/Marcus.txt` строки около 4 слов. В файле этого варианта нет.
- Локальный прогон текущего `groupSentences` на фразе «— Как вчера, триллионы? … — Я в кофеине.» дал 3 строки.
- Локальный прогон строк 61–75 `sources/12/Marcus.txt` дал 8 строк, в каждой 7–10 слов от 3 букв. «Держал для меня дверь.» отдельной строкой не осталось.

### Почему на упрощении выход был в несколько тысяч токенов

- В `post` уже стояло `reasoning.effort: "low"`. Это не `high`.
- Вход около 1700 токенов сходится с одной пачкой плюс текст `shapeTask`.
- Отдельного предела длины ответа нет. В правилах есть «только готовый текст, без пояснений» и запрет пересказывать короче. Это не запрещает модели писать длинное рассуждение, если сервис считает его в токены ответа.

## Допись: выравнивание оригинала и перевода в одной строке

Дата фактов: 2026-10-02. Источник: чат после дописи «строка-кнопка, один перевод». Правки только в `Pages/text.html`. Промпт перевода и нейросеть не трогали. Git commit не делался.

### Задача пользователя

- После ответа перевода желтый английский и серый/синий русский должны читаться «в рамках»: похожие места (запятые, точки, союзы) стоят примерно на одной вертикали, между кусками — пустое место за счёт более короткой фразы, без пробелов внутри куска.
- Выравнивать **начала** частей, не концы. Кусок цельный, текст внутри прижат влево, не растягивать короткий кусок на ширину длинного.
- Якоря (границы кусков): запятые, точки и прочие знаки конца фразы; длинное тире; слова `and`/`и`, `that`/`what`/`что`, `we`/`мы`, а также `they`/`они`, `he`/`он`/`оно`, `she`/`она`. `что` сопрягается и с `that`, и с `what`.
- Дефис внутри слова (`Twenty-six`, `Двадцать-шесть`) **не** режет. Апостроф в `would've` не режет.
- Личные местоимения вроде `я`/`I`, `ты`/`you` как якоря **убраны**: иначе дыра появлялась внутри фразы (`…назад я встретил…`, `…и ты заслуживаешь…`).
- Лишняя запятая или точка в переводе не должна открывать новую колонку и сдвигать хвост. Пример: в оригинале по смыслу `. , .`, в переводе `. , , .` — средняя запятая перевода игнорируется при сопоставлении.
- Позиция якоря считается по **числу букв** от начала строки, не по доле символов (включая лишнюю пунктуацию перевода).

### Что в файле сейчас

**Вёрстка (класс `.src.fit` после успешного `placeAlign`):**

- У `.src` включается `display: flex; flex-wrap: wrap`. Каждая пара — `span.pair`: сверху `span.tbit` (перевод, жёлтый `#f0d24a`), снизу `span.sbit` (оригинал, цвет строки / синий при `live`).
- `flex: 0 0 auto` у `.pair`: ширина колонки по содержимому, короткий кусок не тянется до конца длинного.
- `white-space: pre-wrap` у `.tbit` и `.sbit`, чтобы хвостовой пробел куска не схлопывался к следующему слову.
- Если кусков меньше двух, `placeAlign` возвращает `false`, перевод остаётся в `div.tr` как раньше.
- Клик по `.tbit` не шлёт повторный перевод (`closest(".tbit")` в обработчике).
- `sourceText(node)` читает `dataset.plain` (исходная строка до разметки). `prior`, `pull`, `adapt` и `keepOnly` используют его; при смене строки `unfold` снимает `.fit`.

**Логика (скрипт, после `sourceText`):**

| Функция | Назначение |
|---------|------------|
| `letterMap(s)` | Префиксные суммы букв `\p{L}`; позиция якоря — `letters`, не индекс символа. |
| `anchors(s)` | Список якорей `{ kind, at, letters }`. Виды: `stop` (`.!?…`), `comma` (`,;:`), `dash` (длинное тире U+2012–2015, U+2212), `and`, `that`, `we`, `they`, `he`, `she`. Слова — регистронезависимо. На одной позиции один якорь. |
| `matchedCuts(src, tr)` | Сопоставление двух списков якорей (DP). Пара только при **одинаковом** `kind`; стоимость пары — \|разница букв\| / scale. Якорь только в оригинале — пропуск с штрафом `skipSrc` 0.3. Якорь только в переводе — пропуск с штрафом `skipTrAt(j)` (меньше, если якорь ближе к концу по буквам), чтобы лишняя запятая перевода чаще отбрасывалась. Несовпадение kind при «паре» — штраф 9. На выходе два массива позиций разреза. |
| `splitPair(src, tr)` | Режет обе строки по согласованным `matchedCuts`, склеивает хвост. |
| `placeAlign(block, translated)` | Строит `.pair` в `.src`, очищает `.tr`. |
| `unfold(src)` | Снимает `.fit`, восстанавливает текст из `plain`. |

**`send`:** после `pull` вызывается `placeAlign`; при успехе `tr.textContent = ""`, иначе перевод только в `.tr`.

### Эволюция в чате (кратко)

1. Сначала — доля длины строки по всем знакам с обеих сторон и `snapCut`; лишний знак перевода давал лишнюю колонку («решение», «семьи» у правого края).
2. Потом — разрез только где знак есть в **обеих** строках (по доле длины).
3. Потом — `chunksOf` + DP по доле начала куска; якоря-слова и все тире/дефисы; пользователь указал на разрыв `Twenty-` / `six` и на прилипание «Кайл».
4. Сужение якорей: без дефиса-слова, без `я`/`ты`/…; только длинное тире; слова `and`, `that`/`what`, `we`, `they`, `he`, `she` и русские пары.
5. Текущий слой — `anchors` + `matchedCuts` по **буквам** и типу знака, чтобы лишняя `,` в переводе не сдвигала колонки.

### Пример, к которому стремился пользователь (Kyle)
